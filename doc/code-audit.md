| 顺序 | 范围 | 建议与边界 |

| 1 | `pages/Fiches.py` 656 行 | 抽取纯请求模块 `fiche_requests.py`，集中签署 payload、超时和错误解析；单份与批量共用。再把人员选择、单份操作、批量操作分别提取渲染函数，保留 widget key、调用顺序与状态修改时机。 |

| 5 | `calendar_view.py` 477 行、`ExcelGen.py` 344 行 | 先建立统一的半天状态与时数计算规则，再让日历预览和导出消费同一结果。不可仅删除旧 vacances、absences、arret 字段来减少行数；它们承载历史数据兼容。 |

## 性能优化的代码依据

- `backend/main.py:338` 的 load_user 每人查询账户、两类组关系、合同表存在性及合同历史；all_users 和 list_users 逐人调用，查询数量随人员数增加。改成批量读取账户、成员关系与合同，再组装公共资料；不要缓存 password_hash 或延迟权限撤销生效。
- `pages/TransportReceipts.py:28` 每次 rerun 请求全部可见文件（含归档），然后前端按月和类型过滤。增加兼容旧调用的后端月份、归档、类型过滤与分页；在 SQL 中先执行访问范围条件。前端和后端分别避免重复过滤逻辑。
- `document_ui.py:42` 将每份准备过的文件字节保存在 session，切换月份不会清除；另有最多 100 MiB 原始文件的 ZIP。建立账号内的缓存上限与淘汰规则。大批量下载若需要后台任务，须单独设计任务鉴权和过期清理。
- 单份及批量 PDF 都会通过 LibreOffice 转换。可按原文件内容摘要复用转换结果，但必须同时约束账号、有效期和磁盘清理；不直接缓存公开签署 URL。

- `modules.md` 是首选开发导航，只保留模块职责、最小阅读入口与关键约束。
