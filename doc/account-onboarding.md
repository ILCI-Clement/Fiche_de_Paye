# 初始密码与建号通知（本地开发，未上线）

- Admin / SuperAdmin 建号仍要求分填名、姓和有效邮箱。`POST /create-user` 新增严格布尔字段 `generate_password`，默认 false 保留手动设置。
- true 时不提交 `new_password`；后端用 `secrets` 生成恰好 8 个 A–Z / 0–9 字符，至少包含一位字母和一位数字。手动设置沿用至少 8 字符，并检查 bcrypt 的 72 字节上限。
- 数据库只写 bcrypt 哈希，不写原密码；响应不返回密码。初始密码仅用于本次邮件，邮件包括账号邮箱和 HTTPS 登录地址。随机与手动两种方式均发送建号邮件。
- 创建和角色审计先一起提交、关闭数据库连接，随后仅尝试一次 SMTP 发送；不自动重发或回滚已创建的账号。新邮箱按大小写无关规则查重，失败/重复建号不发邮件。
- `welcome_email_sent` 表示邮件服务器接受发送，不保证到达收件箱。返回 false 时前端明确显示账号已创建，并提示排查邮件配置、通过忘记密码流程处理，不重复创建账号。网络超时提示先检查账号列表。
- 465 使用 SSL，其余端口先 STARTTLS 再认证，均校验证书，连接超时 10 秒；建号请求前端等待上限 90 秒。失败不输出 SMTP 异常、密码或邮件正文。
- 随机模式设置 `users.initial_password_pending=1`；已有账户迁移默认 0，原密码及权限不变。该列由已有账户状态迁移在兼容旧零日期的连接中添加。
- 登录只显示可关闭的建议改密提示，并提供前往 Paramètres 的按钮；不强制修改、不限制正常操作。修改/重置密码后清除标志；替换随机初始密码时撤销该账号原会话及记住登录凭据。
- 本地原有禁建测试账号、禁发邮件策略保留，新增欢迎邮件函数也检查本地环境，不自动给旧账号补发邮件。

发布需同步 React API 与保留 API 的 main、account_lifecycle、account_onboarding、leave_requests 模块，并在新前端前完成增列迁移；不能只发布前端。沿用现有 SMTP 环境配置与 `PRESENCE_APP_URL`，无需生成新密钥。

本轮仅做 Python 语法、前端 lint 与生产构建检查；未运行自动化功能测试、未创建真实账号、未发送邮件。实际收件与邮件服务器配置需在指定测试收件人授权后验证。
