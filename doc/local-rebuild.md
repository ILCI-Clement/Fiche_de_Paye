## 第六阶段：登录补全与签署预检（2026-10-15，本地）

登录支持可选“记住我（30 天）”，复用 `/login` 的 `remember_me`、`/restore-session` 和 `/forget-session`。访问令牌留在 sessionStorage，随机持久令牌留在当前来源的 localStorage；后端仅保存其散列及到期时间。退出会清理浏览器状态并尝试撤销服务端持久令牌，网络失败时浏览器仍清除。访问令牌失效时尝试恢复持久会话；持久会话失效则回登录。资料修改后撤销旧持久令牌，需要重新登录并勾选才再次启用。

## 第八阶段：保存冲突保护与按需加载（2026-10-15，本地）

`attendance_revision.py` 计算不改变存储内容的 JSON 内容指纹。工作区返回 `revision`；新版保存、日历应用、从已有账号打开/创建表单及删除 fiche 都携带读取版本。`main.save_config_checked` 先锁账号行（覆盖尚无 Presence 记录的首次保存），再锁配置行并比较版本。冲突返回 409，不执行账号关联和合同日期同步、不覆盖服务器配置。新保存接口要求版本；新版打开/日历写入缺少版本时返回 428，提示重新加载页面。

保存响应直接返回本次实际写入的规范化配置及版本，避免保存后重新 GET 的间隙读到别人的数据。旧 `/save-config` 保留原参数和响应，仍可无版本保存，故本保护主要覆盖新版客户端之间及新版对已变化数据的覆盖；不能宣称所有旧客户端也已具备冲突保护。账号改名、合同同步等其他业务入口的并发语义尚未统一。

前端保存冲突保留内存草稿，允许下载 JSON 草稿文件；重新读取服务器版本前要求确认替换。不会自动合并或强制覆盖。考勤草稿未保存时切换菜单会提示，继续切换保留已挂载编辑器；退出登录会提示丢弃。浏览器刷新仍使用原 beforeunload 提醒，其他页面表单尚未纳入统一草稿拦截。

通过操作锁避免连续点击发起重叠考勤写入；保存期间阻止人员分页和导航。后台请求失败不再直接卸载已有考勤草稿。各业务页面改为 lazy/Suspense，首次访问加载，已打开模块保留状态；模块加载错误的重试边界待完善。

本次构建入口 JS 从上一轮约 717.04 kB 降到 572.36 kB（gzip 从 215.93 kB 降到 179.32 kB），页面模块单独输出；整体依赖并未全部缩小，主包仍有超过 500 kB 的提示。这是构建产物比较，不是首屏耗时实测。

新增 8 项保存版本测试，覆盖旧路由兼容、同一版本两次保存冲突、冲突不触发合同同步、首次空配置和行锁顺序；完整回归共 106 项通过。类型/构建、Oxlint 通过。在真实独立副本中额外提交无效版本，接口返回 409，前后配置与版本完全一致，未写入变更。浏览器确认本地登录页可打开，尚未登录验证双窗口冲突弹窗和导航提示；未修改真实账户配置、未发送邮件或签署、未发布。
