# Account functions and system access

Implemented locally on 2026-10-29; published 2026-10-30 (Paris). See [release verification](releases/access-export-20261030.md).

`OrganizationFields.tsx` is shared by account organization editing and unified personnel/account registration. Its Fonction selector contains Employé, Responsable and Sans fonction métier (for system-only accounts). Independent Admin and Super Admin checkboxes retain the existing `role_tags` API and storage representation. Selecting a function preserves system access; changing system access preserves the function. Existing mixed business tags are not rewritten on page load. Leaving Responsable clears the managed-department draft as before. Existing backend delegation, self-role protection and last-active-Super-Admin checks remain authoritative.

`SystemAccessFields.tsx` now renders the shared system-access controls. On the account editor they are right-aligned on the same row as the name; they are omitted from the organization accordion. Checking or unchecking opens a compact confirmation dialog. Cancel, Escape and backdrop dismissal leave the draft unchanged; confirmation changes only the draft, never sends the account-update request. Actual changes still require organization save. Registration retains the controls in its form and shares the same confirmation behavior. Browser verification confirmed the header layout and Admin cancellation leaving the checkbox clear; no permissions were submitted.

`person_visibility.account_list_visible` hides a Super Admin account from every other viewer, including another Super Admin. The owner can still see their own account. Catalog filtering applies to account status tabs, organization/team directories, attendance choices, upload assignees, readiness and linked employee-register rows/account searches. Register filtering happens before counts, pagination and current-filter Excel export. A hidden account's private profile and account-personnel projection cannot be opened through a guessed username. Employee rows without an associated account remain visible under their existing register permissions.

Authentication, stored roles and assignments are unchanged. Historical attendance, signed files and audit authors are retained under their existing access rules. Immutable historical register snapshots are not rewritten or deleted; automated snapshot capture retains its existing authorized scope. This is directory visibility, not anonymization of business history or revocation of Super Admin maintenance rights.

Verification: 502 backend tests including local MySQL TEMPORARY-table workflows; 61 frontend tests, lint and production build. Browser observation with a local Super Admin verified separate function/access controls, function options and protected self-access checkboxes; no real account role changes, account creation, emails or signature sends were submitted.
