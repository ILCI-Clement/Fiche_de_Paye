# 邮箱同步与占用规则

本次改动已部署至 `rh-email-identity-20261030T155220Z`，验证记录见 [发布说明](releases/email-identity-20261030.md)。

- 已关联登录账号：修改 Utilisateurs 的邮箱会在同一事务更新登录邮箱；账号设置中修改邮箱也同步关联档案。失败全部回滚，并保留修改审计。
- 未关联账号：只修改档案联系邮箱，不创建或更改登录账号。
- 正常、停用和归档账号均占用邮箱；删除登录、保留历史资料后释放邮箱。比较忽略首尾空格和大小写。
- 邮箱变化撤销旧会话、记住登录和找回密码凭据；本人从账户设置修改时返回新会话。
- 删除登录后仍保留原账号和档案的历史邮箱。新账号拥有不同的账号标识，不通过复用邮箱继承历史文件；无稳定账号标识的旧考勤在邮箱有多个历史所有者时不自动匹配。
- 关联到已删除登录的档案需先解除关联，才能修改该历史联系邮箱。普通 Admin 不能借此更改被隐藏的 Super Admin 账号。

## 实现入口

`backend/account_email.py` 共用可用性检查、双向同步和迁移；`main.py` 负责认证和设置，`personnel_register.py` 提供管理员邮箱可用性查询和档案更新；`PersonnelEditor.tsx` 在邮箱失焦时预检，最终由服务端和数据库唯一约束裁定。

迁移通过数据库级命名锁串行执行：先新增生成列 `login_email_key` 和唯一索引，再移除旧的全历史 email 唯一索引。仅未删除登录生成规范化邮箱，已删除者生成 NULL。遇到已有冲突直接失败，不自动合并账号。为兼容旧零日期默认值，仅在迁移连接内暂时调整相关 SQL 模式并恢复。

## 验证及部署注意

`test_account_email.py` 仅使用 MySQL TEMPORARY 表验证重复占用、删除后复用、登录、签署身份、密码找回、双向同步、权限、会话撤销和事务回滚。未发送真实邮件或修改线上人员资料。

部署前按 `backend/README.md` 备份并比较服务器差异。邮箱复用后不能直接回滚到旧版认证后端：旧代码可能将历史同邮箱记录识别为重复账号。前端可独立回退，认证后端需保留新身份判定；禁止通过清理历史邮箱或合并账号恢复旧约束。
