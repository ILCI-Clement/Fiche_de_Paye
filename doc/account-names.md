# 账号姓名与存储（2026-10-23，本地未发布）

## 数据位置

- `users`：登录邮箱、bcrypt 密码哈希、角色、会话状态、稳定账号标识；新增 `first_name`、`last_name` 两列，分别保存名与姓。新建必填，旧行默认空字符串，不自动拆分姓名或从邮箱猜测。
- `personnel_register*`：独立员工名册、任职经历及修改审计，通过唯一 `linked_username` 明确关联账号。建号不自动生成正式员工档案。
- `personnel_contracts`、`Presence`：合同及考勤继续使用稳定账号关联，不因姓名变化重写历史。
- 社保号继续使用独立的 AES-256-GCM 保护；姓名目录只读取姓名及关联字段，不读取社保号、地址或密码。

## 创建与显示

`POST /create-user` 新增必填 `first_name`、`last_name`，各最多 100 字符，组合后最多 200 字符；拒绝空白或非字符串，保留复姓、连字符和 Unicode，清理多余空白。界面按 Prénoms / Nom 分开输入；登录使用邮箱。未传旧式 `new_username` 时，后端生成 `u_` 加 24 位随机十六进制标识；仍接受旧式明确标识，但旧客户端也必须补齐姓名。

统一姓名目录优先级：

1. 明确关联名册中填写齐全的名 + 姓。
2. 账号填写齐全的名 + 姓。
3. 旧名册原有全名（不拆分、换序或猜测）。
4. 有效邮箱 @ 前的部分；缺失则显示“Nom non renseigné”。

考勤、团队、文件上传人、请假与资料关联选择器复用该目录。同名只影响显示，不改变鉴权；选择器继续用邮箱区分。已有缺项账号可通过名册登记/关联补齐结构化姓名；不会自动改变原登录或权限。

## 验证与边界

- 104 项相关检查通过：必填与 Unicode、创建存储、随机标识、角色审计失败回滚、同名隔离、跨模块名称投影、本人资料权限和旧资料兼容；包括真实 MySQL 连接私有 TEMPORARY 表中的增列与读写验证。
- 本地原有 7 个账号的邮箱、账号标识、密码哈希、权限、会话版本和合同字段摘要在本轮检查前后相同。
- 前端 lint、TypeScript/Vite 构建通过；浏览器确认姓、名分列且 required。本地建号仍按原策略关闭，未在业务副本中实际创建账号；新建路径由隔离测试验证。
- 本轮未更改生产服务器、未发送邮件、未部署。发布需将 `account_names.py`、`person_names.py` 及调用方同步到所有仍可访问的 API，按发布流程备份后迁移。新增列不修改原行，旧二进制可以忽略新列，但旧界面的建号请求需升级后才能继续创建。
