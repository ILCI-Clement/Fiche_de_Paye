# 负责人创建工时表修复（2026-10-27 已上线）

发布版本 `responsable-access-20261027T181526Z` / `a6b9bc8a43e4`，前后端与保留 API 已同步；部署、验证和回退见 [发布记录](releases/responsable-access-20261027.md)。下文保留开发测试过程，其“未上线”描述为当时状态。

修复前有两个独立阻塞：工作区含未关联账号或已离开管理范围的历史表时，整个页面返回 409；目标员工缺少当月合同，则创建返回另一种 409。

## 操作流程

1. Admin 创建登录账号，设置直接负责人；员工名册另行登记并按需关联。
2. Responsable 打开 **Fiches de temps**，选择月份和下属，点击打开／创建。
3. 缺少覆盖该月的合同则显示补录窗口；Admin 或直接负责人可填写真实类型、开始日期和结束日期（CDI 可无结束日期），保存后继续打开工时表。取消不会创建合同。
4. 选择半天、设置状态并应用，保存后可重新打开。导出／签署仍使用原有完整性校验，创建成功不代表可立即发送签署。

已有合同修改、归档与永久删除继续沿用原权限。仅管理同一部门但并非直接负责人时，补录须由 Admin 或直接负责人完成。Admin 与负责人仍使用各自工作区；不自动共享草稿。

## 保护措施

- `/attendance/workspace` 仅返回有权限的表；隐藏条目不返回姓名或内容，只显示数量。
- `/attendance/save`、打开表和日历应用共用锁内保存：先核对完整配置版本，再验证可见表，原样合并服务器中的隐藏历史。拒绝伪造隐藏 ID、越权修改及过期保存。
- 缺合同带 `X-Attendance-Requirement: contract`；其他 409 不触发补录。
- `POST /attendance/contracts/{username}` 创建合同前重新核对数据库角色、直接上下级、账号有效性、日期和重叠；不更新已有合同。
- 合同、名册同步和新增 `contract_setup_events` 审计在同一事务；审计失败全部回滚。启动时创建审计表，部署需更新前后端并先备份。
- 本地启动端口探测改用 Python 标准输入，避免 PowerShell 参数引号导致探测失败；端口进程查询失败时明确中止，不再误报重启成功。
